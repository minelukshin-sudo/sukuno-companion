# Sukuno — голосовой AI-компаньон с 3D-аватаром

Десктопный компаньон для Windows: VRM-аватар в углу экрана поверх всех окон, голосовой ввод
(push-to-talk), ответы голосом через TTS с конвертацией в **ваш RVC-голос** и мозг на Gemini
с вызовом инструментов (открыть приложение, найти файл, поставить напоминание, станцевать).

Стек: **Electron + TypeScript + Vite** (electron-vite) · **three.js + @pixiv/three-vrm** ·
**@google/genai** · **RVC** (rvc-python + PyTorch CUDA) · **Edge TTS / Gemini TTS**.

## Что сделать после скачивания

В репозитории **только код**: `node_modules`, модель аватара, голосовые файлы RVC и окружение Python
намеренно не хранятся — они тяжёлые и у каждого свои. Поэтому после `git clone` или распаковки ZIP:

1. **`npm install`** — поставит зависимости (`node_modules` в репозитории нет). Обязательно.
2. **Положить свой `.vrm` в папку `models/`** — любое имя, главное чтобы расширение было `.vrm`
   (предпочтительно `model.vrm`). Обязательно: без модели аватара запускать нечего.
3. **Запустить `npm start`** (или `start-sukuno.cmd`) и **ввести ключ Gemini** в открывшемся окне
   настроек. Обязательно для чата и голосовых ответов.
4. *(Необязательно)* **Голос RVC**: положить `.pth` и `.index` в `rvc/models/` и один раз выполнить
   `rvc\setup.cmd` — он скачает Python 3.10 и PyTorch с CUDA (~2.5 ГБ) внутрь папки проекта.
5. *(Необязательно)* В настройках включить **«Голос RVC»** и указать пути к `.pth` и `.index`.

Ключ Gemini и остальные настройки в репозиторий не попадают: они лежат в `%APPDATA%\sukuno-companion\`
(ключ — зашифрован через Windows DPAPI), поэтому на новой машине их нужно ввести заново.

Без шагов 4–5 приложение полностью работает: озвучка пойдёт через Edge TTS или системный голос.

## 1. Что положить в `models/`

В папку `models/` нужно положить один файл VRM:

```
models/
  model.vrm          <- предпочтительное имя
```

- Поддерживаются **VRM 0.x** (VRoid Studio) и VRM 1.0 — файл загружается через `@pixiv/three-vrm`
  (`VRMLoaderPlugin`), для 0.x автоматически применяется `VRMUtils.rotateVRM0`.
- Если `model.vrm` нет, приложение возьмёт **первый по алфавиту `*.vrm`** из папки,
  так что переименовывать файл не обязательно. Сами `.vrm` в репозиторий не кладутся — они у каждого свои.
- Файл ~21 МБ: main-процесс читает его с диска (`app.getAppPath()/models` в dev, `process.resourcesPath/models`
  в собранной версии) и передаёт байты в рендерер по IPC, где они разбираются через `GLTFLoader.parse`.
  Никаких `fetch` к локальным файлам нет, `webSecurity` не отключён.
- Мимика: улыбка/танец используют `Joy`, лип-синк — `A`, моргание — `Blink`
  (для VRM 1.0 те же пресеты называются `aa` / `blink` / `happy`; код сам определяет доступные).

## 2. Запуск

Требуется Node.js 20+ (проверено на 22) и Windows 10/11.

### Самый простой способ

Двойной клик по ярлыку **«Сукуно»** на рабочем столе (или файл `start-sukuno.cmd` в папке проекта).
Ярлык запускает `sukuno-hidden.vbs`: он собирает проект и открывает аватар вместе с окном настроек,
без чёрного окна консоли. Первый раз перед этим нужно один раз выполнить `npm install`.

Если ярлыка нет — его можно пересоздать из папки проекта, либо просто пользоваться `start-sukuno.cmd`.

### Вручную из терминала

Откройте **командную строку** (`cmd`) в папке проекта и выполните:

```bat
npm install
npm start
```

В **PowerShell** команда `npm start` на этой машине падает с ошибкой «выполнение сценариев отключено»
(в системе запрещены `.ps1`). Там используйте `npm.cmd start` — или просто запускайте `start-sukuno.cmd`.

`npm start` = `electron-vite dev`: поднимает Vite для рендерера и запускает Electron с HMR.
Ярлык и `start-sukuno.cmd` работают иначе: делают `npm run build` и запускают Electron напрямую
(быстрее, без dev-сервера и без занятого порта).

Полезные команды:

```bash
npm run build      # сборка в out/
npm run typecheck  # tsc --noEmit по main/preload и по renderer
npm run preview    # запуск собранной версии
```

## 3. Первый запуск

1. При старте открывается окно **Настройки** (если ключа ещё нет — или если запущено ярлыком
   с флагом `--sukuno-settings`).
2. Вставьте **ключ Gemini** → «Сохранить». Ключ шифруется через Electron `safeStorage` (DPAPI)
   и лежит в `%APPDATA%\sukuno-companion\apikey.bin`. В открытом виде он нигде не хранится и не логируется.
3. Модель по умолчанию — `gemini-2.5-flash`, меняется в настройках.
4. Там же: имя персонажа, системный промпт (подстановка `{name}`), микрофон, горячая клавиша.
5. Раздел **«Озвучка (голос)»**: провайдер, имя голоса, модель Gemini TTS и кнопка «Проверить голос».

## 4. Озвучка

Три провайдера, переключаются в настройках:

| Провайдер | Голос по умолчанию | Что нужно |
| --- | --- | --- |
| **Edge TTS** (по умолчанию) | `ru-RU-SvetlanaNeural` | ничего, ключ не тратится, работает из РФ |
| **Gemini TTS** | `Kore`, модель `gemini-2.5-flash-preview-tts` | ключ Gemini и VPN |
| **Системный** | голос Windows | ничего (запасной вариант, звучит роботом) |

Как это устроено: main-процесс получает аудио (Edge отдаёт MP3, Gemini — сырой PCM 24 кГц, его
оборачиваем в WAV) и отправляет в рендерер по IPC. Там оно декодируется через Web Audio и играет
по цепочке `BufferSource → AnalyserNode → динамики`, а рот аватара (`aa`/`A`) открывается по
**реальному уровню звука** с анализатора, а не по таймеру. Длинный ответ режется на предложения:
первое играет, пока следующее синтезируется. Остановить речь — кнопка ⏹ на аватаре.

Если провайдер упал (нет интернета, квота, ключ), персонаж переключается на системный голос и
пишет в чат короткую строку вида «Озвучка gemini не сработала — говорю системным голосом. …».

## 5. Голос RVC

Схема: **TTS (Edge/Gemini) → локальный RVC-сервер → воспроизведение**. Лип-синк по-прежнему считается
по реальному звуку с анализатора, поэтому артикуляция совпадает уже со сконвертированным голосом.

Где что лежит:

| Путь | Что это |
| --- | --- |
| `rvc/models/` | ваши файлы голоса: `voice.pth` и `voice.index` (имена любые — реальные пути задаются в настройках) |
| `rvc/venv/` | изолированное окружение: Python 3.10.11 + PyTorch cu118 + rvc-python. Глобально ничего не ставилось |
| `rvc/server.py` | сервер конвертации (FastAPI, только `127.0.0.1`, порт по умолчанию 5055) |
| `rvc/setup.cmd` | пересоздать окружение с нуля (один раз, ~2.5 ГБ загрузок) |
| `rvc/requirements.txt` | список пакетов с пояснениями по версиям |

Что установлено и почему именно так:

| Компонент | Версия | Причина |
| --- | --- | --- |
| Python | 3.10.11 embeddable, внутри проекта | fairseq 0.12.2 падает на 3.11 и не собирается на 3.12+ |
| PyTorch / torchaudio | 2.1.1+cu118 | рекомендован rvc-python; проверено на GPU NVIDIA под Windows |
| rvc-python | 0.1.5 | инференс RVC, умеет подключать `.index` |
| fairseq | 0.12.2 без C-расширений | официальный sdist + штатная ветка `READTHEDOCS=1` (Windows SDK не нужен) |
| pip | 24.0 (закреплён) | pip ≥ 24.1 отказывается читать метаданные omegaconf 2.0.6 |
| setuptools | 75.6.0 | в 81+ удалён `pkg_resources`, который нужен librosa |

**Безопасность `.pth`.** Файл модели — это pickle. Перед запуском я разобрал его статически
(`pickletools`, без исполнения кода): pickle ссылается только на `collections.OrderedDict`,
`torch._utils._rebuild_tensor_v2` и `torch.HalfStorage` — ничего опасного. Дополнительно
`rvc/server.py` перехватывает `torch.load` и **для файла модели принудительно включает
`weights_only=True`** (сама библиотека rvc-python так не делает — она вызывает `torch.load` без этого
флага). Загрузка с `weights_only=True` проходит успешно, то есть код из pickle не исполняется.

Настройки (раздел «Голос RVC»): тумблер вкл/выкл, путь к `.pth`, путь к `.index`,
транспонирование в полутонах, `index rate`, порт сервера, кнопка «Перезапустить сервер RVC»,
статус сервера и кнопка «Проверить голос» (прогоняет полный цикл TTS → RVC и показывает время).

Как это работает по времени: фраза режется на предложения, каждое конвертируется в очереди —
пока играет текущее, следующее уже синтезируется и конвертируется. Каждая фраза логируется:

```
[voice] фраза 1/2: TTS 843 мс, RVC 4202 мс, игра 7871 мс
[voice] фраза 2/2: TTS 61 мс,  RVC 931 мс,  игра 10320 мс
```

Если RVC не успевает за 5 секунд или сервер недоступен — играет обычный TTS, а в чат уходит
короткая заметка. Первый запуск сервера занимает ~35 секунд (загрузка модели и базовых HuBERT/RMVPE);
статус виден в настройках, при ошибке там же показывается её текст.

## 6. Управление

| Действие | Как |
| --- | --- |
| Меню | правый клик по аватару → Чат / Настройки / Выход |
| Push-to-talk | кнопка 🎙 (нажать — запись, нажать ещё раз — отправить) |
| Push-to-talk (глобально) | `Ctrl+Shift+Space` из любой программы (настраивается) |
| Чат текстом | окно «Чат» из меню |
| Танец | кнопка 🎵 или инструмент `dance` |
| Остановить речь | кнопка ⏹ на аватаре |

Аватар следит за курсором (голова + глаза), дышит и моргает в покое, открывает рот,
пока говорит (озвучка идёт выбранным TTS-провайдером, амплитуда берётся с анализатора),
и танцует под музыку: `AnalyserNode` с микрофона управляет костями; если микрофона нет —
включается синтетический бит, танец всё равно работает.

Прозрачные поля окна «сквозные» для кликов: мышь проходит к окнам за аватаром, а по самому
аватару работает как обычно (порог задаётся `window.hitInset` в `config.json`).

## 7. Инструменты Gemini

| Инструмент | Что делает | Подтверждение |
| --- | --- | --- |
| `open_app` | запускает приложение **только из белого списка** в `config.json` | да |
| `open_url` | открывает ссылку http/https в браузере | да |
| `search_files` | ищет файлы в Документах / Загрузках / Рабочем столе | нет |
| `press_keys` | отправляет нажатия клавиш в активное окно (SendKeys) | да |
| `set_reminder` | напоминает вслух через N минут | нет |
| `dance` | включает/выключает танец | нет |
| `remember_fact` | сохраняет факт о пользователе в `memory.json` | нет |

Удаления файлов нет ни в одном инструменте. Опасные операции спрашивают разрешение в диалоге;
флаги `confirm.*` в `config.json` можно выключить, но по умолчанию они включены все.
`press_keys` запоминает активное окно до показа диалога и возвращает ему фокус перед вводом.

## 8. `config.json` (рядом с `package.json`)

```jsonc
{
  "gemini":  { "model": "gemini-2.5-flash", "systemPrompt": "…{name}…" },
  "character": { "name": "Сукуно" },
  "window":  { "corner": "bottom-right", "width": 420, "height": 620, "margin": 24, "hitInset": 70 },
  "hotkey":  "CommandOrControl+Shift+Space",
  "modelFile": "model.vrm",
  "appWhitelist": [ { "name": "Блокнот", "path": "notepad.exe" } ],
  "confirm": { "open_app": true, "open_url": true, "press_keys": true },
  "tts": {
    "provider": "edge",
    "geminiModel": "gemini-2.5-flash-preview-tts",
    "geminiVoice": "Kore",
    "edgeVoice": "ru-RU-SvetlanaNeural"
  },
  "rvc": {
    "enabled": true,
    "model": "rvc/models/voice.pth",
    "index": "rvc/models/voice.index",
    "pitch": 0,
    "indexRate": 0.6,
    "port": 5055
  }
}
```

`corner`: `bottom-right` / `bottom-left` / `top-right` / `top-left`.
`appWhitelist`: `path` может быть `exe` из `PATH` или полным путём к файлу; `.cmd`/`.bat` тоже работают.
Каталог `models/` и `config.json` берутся из корня проекта (`app.getAppPath()`).

Данные пользователя (не в проекте):

```
%APPDATA%\sukuno-companion\settings.json   — модель, имя, промпт, микрофон, хоткей
%APPDATA%\sukuno-companion\apikey.bin      — ключ, зашифрованный safeStorage
%APPDATA%\sukuno-companion\memory.json     — факты о пользователе
```

## 9. Если что-то не работает

- **Нет русского голоса.** Windows → «Параметры» → «Время и язык» → «Речь» → добавьте русский голос.
  Без него Chromium озвучит текст голосом по умолчанию.
- **Не записывает микрофон.** Проверьте, что в настройках выбран нужный микрофон и что Windows
  разрешает приложению доступ к нему.
- **Горячая клавиша не срабатывает.** Сочетание занято другой программой — смените его в настройках
  (в поле хоткея просто нажмите новое сочетание).
- **Танец не реагирует на музыку.** Микрофон должен «слышать» колонки; иначе работает синтетический бит.
  Танец вообще не зависит от Gemini — он полностью локальный.
- **Gemini отвечает ошибкой («модель недоступна» и т. п.).** Порядок проверки:
  1. **Имя модели.** `gemini-1.5-*` Google отключил, такие запросы возвращают NOT_FOUND.
     Рабочий вариант по умолчанию — `gemini-2.5-flash`.
  2. **Регион.** Gemini API не обслуживает РФ: важен IP, с которого уходит запрос. VPN должен быть
     системным (без раздельного туннелирования), иначе запрос уходит напрямую и Google отвечает
     «User location is not supported». Это же касается запроса на список моделей.
  3. **Ключ.** Отозванный/чужой ключ даёт API_KEY_INVALID.
  В «Настройках» есть кнопка **«Проверить подключение»** — она покажет точную причину и список моделей,
  доступных вашему ключу. Сырой ответ API дублируется серой строкой в окне чата.
- **Модель не грузится.** Проверьте, что в `models/` лежит `.vrm`: в сообщении об ошибке указан полный путь,
  который приложение пыталось прочитать, а настоящая ошибка печатается в консоль main-процесса (`npm start`).
- **Окно с непрозрачным фоном вместо прозрачного.** Electron на Windows рисует прозрачные окна только при
  аппаратном ускорении. При старте приложение проверяет `app.getGPUFeatureStatus()`: если там
  `gpu_compositing = disabled_software` (виртуалка, RDP, нет драйвера GPU), в консоль выводится
  предупреждение — в такой среде прозрачность невозможна, аватар будет на сплошном фоне.
- **RVC не отвечает / статус «не работает».** В настройках виден текст ошибки. Частые причины:
  нет `rvc/venv` (запустите `rvc\setup.cmd`), неверный путь к `.pth`, порт 5055 занят другой программой.
  Лог сервера печатается в консоль приложения с префиксом `[rvc-server]`.
- **Голос в RVC звучит не так.** Покрутите `index rate` (ближе к 0.7 — похожее, но менее стабильно)
  и транспонирование: если базовый голос TTS другого пола, чем модель, помогает сдвиг на ±12 полутонов.
